# hermes-voice

Голосовой слой для **Hermes Agent**. Превращает речь в текст, отдаёт текст модели,
озвучивает ответ — так, чтобы с агентом можно было разговаривать, а не переписываться.

Запускается рядом с gateway на той же машине и добавляет к нему голос. Логику диалога
не дублирует: и агент, и модель — те же, что у Hermes.

## Зачем отдельный сервис

У Hermes есть голосовой стек (`tools/voice_live.py`, `tools/tts_streaming.py`), но он
работает **только внутри десктоп-приложения**: API-сервер отдаёт
`audio_api: False`, `realtime_voice: False`. Мобильному клиенту подключиться не к чему.

Поэтому голосовой слой вынесен наружу — как отдельный HTTP/WebSocket-сервис.

## Два режима ответа

Главная развилка: отвечать быстро или отвечать умно. Совместить не выходит — замеры
на этом железе (Ryzen 5 3500U, провайдер `kodikrouter` → `deepseek/deepseek-v4-flash`):

| Режим | Что это | Первый токен | Инструменты |
|-------|---------|--------------|-------------|
| `direct` | прямой вызов модели, без агентной обвязки | **0.8–3.6 с** | нет |
| `agent` | полный Hermes Agent | **5–17 с** | веб, файлы, память |

Агент тратит время на системный промпт, выбор инструментов и их вызовы. Для голоса
это много: человек уже договорил и ждёт. Поэтому по умолчанию — `direct`, а `agent`
переключается на лету командой `config` (в приложении это кнопка «Быстрый / Агент»).

## Что используется

| Слой | Решение | Первый звук | Стоимость |
|------|---------|-------------|-----------|
| Распознавание речи | `faster-whisper` (CPU, `base`, `float32`) | 1.5–1.8 с на 4–5 с речи | бесплатно, локально |
| Синтез речи | **`piper`** (ONNX, CPU) | **0.24–0.91 с** | бесплатно, локально |
| Синтез речи (опция) | `edge-tts` (облако Microsoft) | 2.1–6.7 с | бесплатно, но сеть |
| Детект речи (VAD) | энергетический, адаптивный порог | — | бесплатно, локально |
| Ответ | `direct` (модель) или `agent` (Hermes) | — | — |

Внешних ключей (OpenAI, ElevenLabs) не требуется.

### Почему Piper, а не edge-tts

edge-tts звучит богаче и голосов у него больше, но для живого диалога он не годится:
первый байт приходит только после того, как Microsoft отбуферизует кусок текста.
Канал тут ни при чём — ping до их узла 52 мс, TLS-рукопожатие 0.39 с.

Замеры первого байта на разной длине текста:

| Символов | edge-tts | piper |
|----------|----------|-------|
| 15 | 2.06 с | — |
| 23 | 2.06 с | **0.24 с** |
| 60 | 4.23 с | — |
| 129 | 5.53 с | — |
| 145 | ~6.0 с | **0.91 с** |

Piper дополнительно генерирует ~9× быстрее реального времени (10.9 с аудио за 1.2 с),
не зависит от сети и не имеет лимитов. Голосов у него меньше, но их можно добавлять
файлами (см. «Голоса»).

## Отбивки: чем закрыть тишину, пока модель думает

Даже с прямым бэкендом ответ приходит за 1–5 с, и всё это время в наушнике тишина.
Разговор от этого перестаёт быть разговором. Живой человек на таком месте говорит
«так…», «сейчас» — сервис делает то же самое.

Короткие фразы (`Так…`, `Секунду…`, `Сейчас.`, `Ага…`) синтезируются **на старте**
и лежат готовыми в памяти. Синтезировать их в момент ожидания бессмысленно — это
та же самая задержка.

Логика адаптивная, а не безусловная:

1. Ждём первый кусок ответа не дольше `filler_delay_ms`.
2. Ответ успел → отбивка **отменяется**, тишины и не было.
3. Не успел → отдаём случайную отбивку, она приходит мгновенно.

Замер (порог поднят до 5 с, чтобы увидеть обе ветки):

| Вопрос | Ответ пришёл | Отбивка |
|--------|--------------|---------|
| «Привет!» | 5.02 с | да, на 5.02 с |
| «Спасибо» | 2.96 с | **нет** |
| «Как дела?» | 1.95 с | **нет** |

С рабочим порогом 700 мс тишина перед ответом сокращается с 3.7 с до 0.7 с.
Отбивка помечается в протоколе полем `"filler": true` и `seq: -1`, чтобы клиент
не путал её с текстом ответа.

Отключается через `filler_enabled: false`.

## Итоговая задержка

Две разные метрики, их легко перепутать:

**От конца речи до первого звука** — то, что чувствует человек:

```
VAD закрыл фразу      ~1.1 с   (vad_silence_ms)
распознавание         ~1.5 с   (base, 4 с речи)
ответ модели           1–5 с   (direct; разброс провайдера)
синтез первого куска  ~0.5 с   (piper)
──────────────────────────────
итого                 ~4–8 с
```

**С отбивками** тишина перед ответом сокращается до `filler_delay_ms` (700 мс) —
человек слышит реакцию почти сразу, а не через четыре секунды.

**От конца распознавания до первого звука** — то, что печатает `smoke_test.py`
(событие `transcript` уже после STT): **1.5–5.3 с** по замерам.

Было с агентом и edge-tts: **11–20 с** по той же метрике. Всё, что осталось ниже
5 с, упирается уже в провайдера модели, а не в голосовой слой.

## Установка и запуск

```bat
run.bat
```

Скрипт создаст `.venv`, поставит зависимости, скачает голоса (если их нет) и поднимет
сервис на порту **8643**.

Проверка:

```bash
curl http://localhost:8643/health
```

### Голоса

Голоса Piper — это файлы `voices/<имя>.onnx` + `<имя>.onnx.json`.
Скачать русские (женский и три мужских):

```bash
cd voices
for v in irina dmitri ruslan denis; do
  base="https://huggingface.co/rhasspy/piper-voices/resolve/main/ru/ru_RU/$v/medium/ru_RU-$v-medium"
  curl -L -o "ru_RU-$v-medium.onnx" "$base.onnx"
  curl -L -o "ru_RU-$v-medium.onnx.json" "$base.onnx.json"
done
```

Каждый голос — ~60 МБ и ~4 с на загрузку. Сервис прогревает их все на старте
(`tts_preload_all`), иначе первое переключение голоса стоит четыре секунды тишины.

## Настройка

`config.json` рядом с проектом либо переменные окружения (`HV_*` важнее файла).

| Ключ | По умолчанию | Смысл |
|------|--------------|-------|
| `port` | `8643` | порт сервиса |
| `hermes_base_url` | `http://127.0.0.1:8642` | адрес Hermes Gateway |
| `hermes_api_key` | — | ключ API-сервера Hermes |
| `hermes_model` | `hermes-agent` | модель агента |
| `voice_backend` | `direct` | `direct` (быстро) или `agent` (инструменты) |
| `direct_base_url` | пусто | адрес провайдера; пусто — берётся из конфига Hermes |
| `direct_api_key` | пусто | ключ провайдера; пусто — берётся из `.env` Hermes |
| `direct_model` | пусто | модель; пусто — берётся из конфига Hermes |
| `direct_max_tokens` | `400` | предел длины ответа (для голоса длинные не нужны) |
| `direct_temperature` | `0.6` | температура |
| `stt_model` | `base` | модель whisper: `base` быстрее, `small` точнее |
| `stt_compute` | `float32` | тип вычислений (на этом CPU `int8` **медленнее**) |
| `stt_threads` | `8` | потоков CPU для распознавания |
| `stt_language` | `ru` | язык распознавания |
| `stt_warmup` | `true` | прогревать модель при старте |
| `tts_engine` | `piper` | `piper` (локально, wav) или `edge` (облако, mp3) |
| `tts_voice` | `ru_RU-irina-medium` | голос по умолчанию |
| `tts_voices_dir` | `voices` | каталог с голосами piper |
| `tts_piper_rate` | `1.1` | темп piper: 1.0 — как записан, 1.1 — на 10% быстрее |
| `tts_warmup` | `true` | прогреть голос при старте |
| `tts_preload_all` | `true` | прогреть **все** голоса в фоне |
| `filler_enabled` | `true` | вставлять отбивку, пока модель думает |
| `filler_delay_ms` | `700` | сколько ждать ответ, прежде чем вставить отбивку |
| `filler_phrases` | `["Так…","Секунду…","Сейчас.","Ага…"]` | сами отбивки |
| `tts_first_chunk_chars` | `60` | минимальная длина первого куска озвучки |
| `tts_chunk_chars` | `220` | длина последующих кусков |
| `vad_silence_ms` | `1100` | сколько тишины считать концом фразы |
| `vad_start_ratio` | `2.6` | во сколько раз речь громче шума |
| `vad_pre_roll_ms` | `350` | запас перед началом речи |

Прямой режим по умолчанию берёт модель из конфига Hermes (`config.yaml` + `.env`),
чтобы не дублировать настройки руками: поменяешь модель у агента — голос поедет на ней же.

### О выборе модели распознавания

Замеры на этой машине, аудио 5.69 с:

| Модель | compute | потоки | Время | Коэффициент |
|--------|---------|--------|-------|-------------|
| `base` | `float32` | 8 | 1.46 с | **0.26×** |
| `base` | `int8` | 8 | 1.71 с | 0.30× |
| `small` | `int8` | 8 | 5.04 с | 0.89× |
| `small` | `float32` | 8 | 5.65 с | 0.99× |

Коэффициент — отношение времени распознавания к длительности аудио. Меньше 1.0 значит
быстрее реального времени. `int8` проигрывает, потому что у Zen+ нет AVX-512.
Модель `small` точнее расставляет знаки препинания, но работает на пределе.

## HTTP API

### `GET /health`
Живость сервиса, доступность Hermes и прямого режима.

### `GET /v1/voices`
Голоса активного движка.

### `POST /v1/audio/transcriptions`
Совместимо с OpenAI. Принимает `multipart/form-data` с полем `file`
(wav, mp3, ogg, webm, m4a) и необязательным `language`.

```bash
curl -X POST http://localhost:8643/v1/audio/transcriptions \
  -F "file=@voice.wav"
# {"text": "привет, гермес", "elapsed": 1.24}
```

### `POST /v1/audio/speech`
Совместимо с OpenAI. JSON `{"input": "текст", "voice": "ru_RU-irina-medium"}`.
Ответ — `audio/wav` при движке piper, `audio/mpeg` при edge.

```bash
curl -X POST http://localhost:8643/v1/audio/speech \
  -H "Content-Type: application/json" \
  -d '{"input":"Привет! Как дела?"}' -o reply.wav
```

## WebSocket: `ws://<host>:8643/v1/voice`

Основной режим. Двусторонний канал: клиент шлёт микрофон, сервер возвращает
события и звук.

### Формат аудио

**От клиента:** сырой PCM, `signed 16-bit little-endian`, **16 кГц, моно** —
бинарными фреймами. Чанки по 20–40 мс (640–1280 байт).

**От сервера:** бинарные фреймы. Формат и частота приходят в `hello.output`
(`wav`/22050 у piper, `mp3` у edge).

**Гарантия протокола:** все бинарные фреймы между двумя `speech_chunk` образуют
**один цельный, готовый к проигрыванию файл**. Клиенту не нужно ничего склеивать
и разбирать — сохранил и проиграл. Именно поэтому wav (а не сырой PCM): у него
есть заголовок, и файл самодостаточен.

### Сообщения от клиента (текстовые фреймы, JSON)

| Сообщение | Действие |
|-----------|----------|
| `{"type":"start"}` | начать слушать (можно указать `voice`, `session_id`) |
| `{"type":"stop"}` | остановить слушание |
| `{"type":"interrupt"}` | прервать текущий ответ |
| `{"type":"text","content":"..."}` | отправить текст без голоса (`text` — алиас) |
| `{"type":"config","voice":"..."}` | сменить голос на лету |
| `{"type":"config","backend":"agent"}` | сменить бэкенд: `direct` или `agent` |
| `{"type":"ping"}` | проверка связи |

### Сообщения от сервера (JSON)

| Сообщение | Смысл |
|-----------|-------|
| `{"type":"hello", ...}` | параметры сессии: формат вывода, голоса, бэкенды |
| `{"type":"state","value":"listening"}` | слушаю / `thinking` / `speaking` / `idle` |
| `{"type":"level","value":0.42}` | громкость микрофона, 0..1 (для анимации) |
| `{"type":"transcript","text":"...","final":true}` | что распознано |
| `{"type":"assistant_delta","text":"..."}` | кусок ответа (стриминг текста) |
| `{"type":"speech_chunk","seq":0,"text":"..."}` | **начало куска озвучки** |
| `{"type":"speech_chunk","seq":-1,"text":"","filler":true}` | отбивка: не текст ответа |
| `{"type":"assistant_done","text":"..."}` | ответ целиком |
| `{"type":"config","voice":"...","backend":"..."}` | подтверждение смены настроек |
| `{"type":"error","message":"..."}` | ошибка |
| `{"type":"pong"}` | ответ на ping |

### Цикл диалога

1. Клиент подключается, шлёт `config` (голос, бэкенд) и `start` → `state: listening`.
2. Стримит PCM. Сервер сам определяет начало и конец фразы по паузам —
   кнопку «стоп» нажимать не нужно.
3. Фраза распознана → `transcript` → `state: thinking`.
4. Модель отвечает потоком → `assistant_delta`, а озвучка начинается
   с первого же готового предложения → `speech_chunk` + бинарные фреймы →
   `state: speaking`.
5. Ответ закончился → `assistant_done` → снова `state: listening`.

**Прерывание (barge-in):** если во время `speaking` в микрофон попадает речь,
сервер сам обрывает озвучку и переходит к слушанию — перебивать можно голосом.
Во время `thinking` речь не прерывает запрос: иначе терялось бы начало фразы.

**Очередь:** если человек заговорил, пока модель ещё отвечает, фраза не теряется —
она уходит в очередь и обрабатывается, как только освободится конвейер.

## Проверка

```bash
.venv\Scripts\python.exe tools\smoke_test.py --ws
```

Выводит задержку «конец фразы → первый звук», количество кусков озвучки и проверяет,
что всё аудио пришло внутри кусков (ни одного «сиротского» байта).

```bash
.venv\Scripts\python.exe tools\test_resample.py      # микрофон любой частоты
.venv\Scripts\python.exe tools\test_voice_config.py  # согласование голоса
```

`test_voice_config.py` — регрессия на случай, который уже случался: клиент хранит
голос, выбранный при другом движке TTS, сервер его отвергает, и озвучки нет вовсе.
Тест проверяет, что пустой голос игнорируется молча, чужой отвергается со списком
допустимых, а верный подтверждается.
